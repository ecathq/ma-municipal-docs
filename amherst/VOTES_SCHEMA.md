# votes.json — structured roll-call layer

Generated by `build_votes_dataset.py` from `amherst/votes/*.md`. This is the
aggregation feed the chatbot can't compute on its own (cross-meeting counts,
per-councilor patterns, topic filters) and the data source for json-render views.

## Grain

One record = **one councilor's vote on one motion** (a "ballot").

```json
{
  "councilor": "Schoen",          // null on non-attributable motion stubs
  "vote": "abstain",              // yes | no | abstain | absent | null
  "date": "2021-04-05",
  "meeting_adid": 13134,
  "motion_id": "2021-04-05-adid13134-m7",
  "motion_text": "In accordance with Charter Sec. 5.6, having been published…",
  "topic_tags": ["jones-library", "budget-appropriation"],
  "tally": "10-2-1",              // yes-no-abstain as printed in the record
  "vote_method": "voice_expanded",
  "source_pdf": "https://www.amherstma.gov/Archive.aspx?ADID=13134"
}
```

## The one guarantee

**Every attributed ballot reconciles exactly with the printed tally.** The
extractor tries several parsing strategies per motion and only emits individual
votes when the reconstructed yes/no/abstain counts match the official tally
character-for-character. Motions it cannot reconcile are kept as motion-level
stubs (`councilor: null`, `vote_method: "non_attributable"`) so nothing is
silently dropped — but no individual vote is ever guessed.

## vote_method values

| method            | how the ballots were derived                                  |
|-------------------|---------------------------------------------------------------|
| `roll_call`       | named roll call (inline `Yes Name…` or `Aye:`/`Nay:` blocks)  |
| `voice_named`     | non-roll-call vote with names listed                          |
| `voice_expanded`  | tally + named exceptions (`…DuMont Abstained; Bahl-Milne absent`); present default to yes |
| `unanimous`       | "Unanimous" expanded against the meeting roster               |
| `voice_unanimous` | `X-0-0` tally, no names; present default to yes               |
| `non_attributable`| stub only — could not reconcile to individuals               |

## Coverage (current corpus)

- 184 source meeting files
- ~6,600 attributed ballots across ~507 reconciled motions, 29 councilors
- ~1,240 motions kept as non-attributable stubs

## Known limitations

- **Topic tags are keyword heuristics** over `motion_text` (e.g. `jones library`,
  `appropriat`, `zoning`). Good for filtering, not authoritative classification.
- **Coverage skews to contested votes.** Many unanimous voice votes reconcile
  trivially; a chunk of older prose-formatted records don't reconcile and stay
  as stubs, so they're excluded from per-councilor counts.
- **Name normalization** keeps councilors appearing on ≥3 meeting rosters, which
  drops one-off staff/guests but may also drop a councilor present at very few
  meetings. Bump `min_files` in `build_canon()` to tune.

## Rebuild

```bash
python3 build_votes_dataset.py        # writes amherst/votes.json
open amherst/votes-explorer.html      # self-contained explorer (data embedded)
```
